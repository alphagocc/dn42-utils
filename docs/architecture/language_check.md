# 中文语言规范校验

`AGENTS.md` 的 `Chinese Language Policy` 约束仓库内的中文行文。`scripts/check_language.py` 把其中可机械判定的部分实现为提交前校验,由 `.githooks/` 下的两个 hook 触发。

## 启用

```bash
git config core.hooksPath .githooks
```

设置一次即可。该配置属于仓库级,写在 `.git/config`;各 worktree 共用同一份 `.git`,因此主检出与全部 worktree 同时生效。更换机器后重新执行一次。

`.githooks/pre-commit` 校验本次 staged 的文本文件,`.githooks/commit-msg` 校验提交信息。两者都优先使用 `uv run python`,在没有 uv 的环境下回退到 `python3`——校验器只用标准库,两种方式行为一致。

校验读取的是工作区内容而非 index 版本。部分暂存时,未暂存的改动也会一并检查,报出的行号与编辑器所见一致。

## 命中分级

校验器把规范里的禁用词分成两级。

**拦截级**返回退出码 1,git 据此中止提交。它包含规范 1.1 的禁用表达、1.6 的禁用措辞与禁用句式,以及 1.5 中的管理黑话。1.5 里另有五个词经逐条查证确属滥用,一并纳入:「走」在既有文档中出现于「走 gpg」「稳态同步走」,规范写法是「使用」或「经由」;「落盘」应写「写入文件」;「坑」应写「问题」;「粒度」应写「以 X 为单位」或「每 N 一次」;「对齐」在非内存语境下应写「解析到」或「统一到」。

拦截级另有一条不是词而是标点:规范 1.8 的排版要求下,破折号不该出现在正文里。中文破折号写作两个全角横线,单个的多为误用,两种写法都拦截。

**提示级**只打印,不影响退出码。它收纳 1.5 中在正式出版物与学术论文里通行的计算机领域术语,例如链路、收敛、迭代、路径。依据是规范 1.5 自述的判断标准——只在互联网社区和企业内部流通的词才算黑话,这些词不满足该标准。「链路」与「收敛」的理由更强一层:它们是网络与路由的标准译名(链路本地地址、路由收敛),正当用法无法用有限白名单穷举,因此即使存在被滥用的写法也只提示。「复现」与「重现」等义、「有感知」与「可察觉」等义,两种写法都可接受,同样归入提示级。

`--strict` 把提示级一并升为拦截。

## 子串排除

短词必须配排除表,否则误判会压过真实命中。仓库里「定性」的全部命中都来自「确定性、幂等」,「稳」的命中来自「稳定」与「稳态」。「对齐」属于另一种情形:词本身在拦截级,而「内存对齐」「字节对齐」是硬件术语,靠排除表把它们从匹配中摘出去。

校验器在匹配前先把排除表中的长词从行内抹去,再查找目标词。同一段文字只归属一次:「更稳」命中拦截级后,提示级的「稳」不会重复报出。

排除表位于 `scripts/check_language.py` 的 `EXCLUSIONS`,新增正当长词时补在那里。

## 检查范围

含中文字符的行才进入检查,纯 ASCII 行跳过。文件按扩展名筛选,限于 `.md`、`.py`、`.toml`、`.yml`、`.yaml`、`.txt`、`.j2`、`.sql`。

`AGENTS.md` 及其符号链接 `CLAUDE.md`、校验器自身、它的测试与本文档都不参与检查——这些文件把禁用词当数据列举,检查它们等于检查词表自身。该清单位于 `SELF_REFERENTIAL`。

除词表外还有三条规则。提交信息以问号结尾判为拦截,对应规范 1.9;提交信息中行首出现 `-` 判为提示,对应规范 1.8,Markdown 与 YAML 里该写法必要,只有提交信息才算违规;Markdown 标题内出现 `1)` `a)` 形式的括号编号判为提示,同样对应 1.8。

规范 1.7 的单字替代不做检查。「若」「如」与「若干」「例如」「如下」难以用规则区分,误判过多。

## 豁免

确需保留某行写法时,在该行任意位置添加 `lang-ok` 标记,整行跳过。

临时跳过全部 hook 使用 git 原生的 `git commit --no-verify`。

## 普查与存量

```bash
uv run python scripts/check_language.py --all
```

检查仓库全部文本文件,而非仅 staged 内容。首次启用前跑一遍可以看清存量规模。

命中拦截级时,输出末尾会建议把命中行连同 `AGENTS.md` 的 `Chinese Language Policy` 一并交给 sub agent 复查,由它逐条给出符合规范的替换措辞,人工确认后再修改。逐条判断用词是否属于滥用需要语境理解,这部分不适合用规则表达。
