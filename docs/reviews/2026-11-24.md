## P1 · 配置损坏会把清理目标切换到系统默认目录

`node apply` 和常驻 agent 都会读取本机 `config.toml`。文件缺失、读取失败、TOML 语法错误和字段无效都会抛出 `ConfigError`。`apply()` 捕获后把所有输出位置切换到内置默认值，并在这些位置按文件名前后缀清理过期配置。对于使用自定义目录的节点，一次配置编辑错误就可能让进程写入 `/etc/bird`、删除 `/etc/systemd/network` 下符合命名规则的文件。实际删除需要进程具有该目录的写权限。[配置读取](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/config.py#L73) · [回退与过期文件清理](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/node_apply.py#L461)

隔离实测将默认目录映射到临时目录，放入 `wg_aux.netdev`，然后让已有的配置文件含有 TOML 语法错误。`node apply --dry-run` 返回成功，并将该文件列为 `stale, 将删除`。正式应用对这份清单逐项调用 `unlink()`。[清理范围](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/node_apply.py#L391) · [删除操作](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/node_apply.py#L501)

建议在配置读取接口区分文件缺失和文件不可用。仅在约定允许缺省且文件确实缺失时使用默认值，其他加载错误应在生成写入或删除清单之前返回，并指出问题文件。

## P1 · 重用同一缓存会应用前一个节点的 WireGuard 身份

`node.toml` 支持修改 `node_id`，缓存默认使用固定的 `node-cache.sqlite3`。缓存表只有一行，写入时只要求载荷包含 `revision`，读取时也未核对载荷中的 `node_id`。重新注册节点或从旧节点恢复缓存后，`node apply` 因此可能把旧节点的 peer 和私钥写入当前节点。常驻 agent 启动时先应用缓存，随后才连接中心，中心不可达会延长影响。[缓存读写](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/node_agent.py#L51) · [agent 启动顺序](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/node_ws_agent.py#L263)

隔离实测先以 A 的身份保存含一个 BGP peer 的缓存，再用 B 的 `node.toml` 指向相同缓存。`node apply --no-reload` 返回成功，并将 A 的测试私钥写进 B 的 `.netdev`。建议保存前核对载荷所属节点，读取时也核对身份。节点发生变化后，将该节点视为尚无可用缓存，等取得匹配的期望配置再应用。[应用入口](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/node_apply.py#L454)

## P1 · 导入已有隧道的扫描报告会生成新的本端身份

触发入口是运维显式提交 `node report --kind scan_result --json …`，再由管理员执行 `node import-report` 导入中心尚无记录的 peer。`node report` 发送调用方提供的 JSON。常驻 agent 自动上报的是应用结果，本地 `dn42ctl scan` 则直接把扫描得到的密钥与本端地址写入本地库。这三条路径的数据流不同。[报告提交](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/cli.py#L1721) · [agent 自动上报](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/node_ws_agent.py#L170) · [本地扫描入库](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/scan.py#L483)

报告导入调用 `create_bgp_peer()` 或 `create_ibgp_peer()`，仅转交对端等字段。即使报告带有现有本端密钥对、`local_lla` 和 `allowed_ips`，导入也会重新生成本端密钥、LLA，并使用默认 AllowedIPs。下发该状态后，已配置旧公钥的对端将无法与新身份握手。自定义窄前缀也可能被默认的较宽范围取代。[报告导入](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/report_import.py#L23) · [BGP 创建](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/bgp.py#L78) · [iBGP 创建](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/ibgp.py#L110)

隔离实测向报告服务提交了一条带合成密钥、`local_lla` 和单个 `/48` AllowedIP 的 BGP 记录。通过 CLI 导入后，中心生成的 desired state 含有新生成的合成密钥、新 LLA 和默认前缀 `fe80::/64`、`fd00::/8`。iBGP 的字段遗漏经静态代码核对。建议为接管已有隧道定义单独的导入契约，校验并保留原身份和前缀。无法恢复原身份时，在写入之前让操作者明确选择重新配对。

## P2 · 守护进程重载失败后，相同配置不会自动重试

`node apply` 先写配置文件，再依据本轮文件内容差异调用 `networkctl reload` 或 `birdc configure`。重载失败后磁盘已经是新内容，守护进程可能仍使用旧配置。后续即使中心再次下发同一 revision，磁盘内容比较也会得出零变更。`node once` 和 WebSocket agent 上报的顶层 `ok` 此时仍为 `true`，失败仅列在 `reloads` 和 `warnings` 中。[重载选择](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/services/node_apply.py#L508) · [一次性命令上报](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/cli.py#L1553) · [常驻 agent 上报](https://github.com/alphagocc/dn42-utils/blob/06eba96f915deaaf3bf9dff48262fa5edbdc34a7/src/dn42ctl/node_ws_agent.py#L175)

隔离实测让两条重载命令在第一次 `node apply` 均返回失败，CLI 打印警告并以 0 退出。再次应用相同缓存时，四个生成文件均显示 `unchanged`，重载调用数为零。建议分别记录配置写盘状态和每个守护进程待完成的重载，下一轮只重试失败项，成功后再清除待办状态。
